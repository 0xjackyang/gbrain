# v0.10.2 Migration: Repo-Scoped Sync State

This migration changes how GBrain remembers sync progress.

## What Changed

### Sync anchors are now repo-scoped

GBrain used to store one global sync checkpoint in these config keys:

- `sync.last_commit`
- `sync.last_run`
- `sync.repo_path`

That meant syncing a second repo or linked worktree could overwrite the anchor
for the first repo. On the next sync, GBrain could see an unrelated commit,
fail the ancestor check, and fall back to a full reimport.

GBrain now keeps the authoritative sync anchor under repo-scoped keys. The
legacy global keys are still shadow-written for rollback compatibility, but they
are no longer the source of truth for incremental sync.

## Agent / Operator Instructions

### Step 1: Re-run sync once for each actively managed repo/worktree

```bash
gbrain sync --repo /path/to/brain
```

This seeds the repo-scoped checkpoint if it does not already exist.

### Step 2: Use sync status instead of reading raw `sync.*` config keys

```bash
gbrain sync --status --repo /path/to/brain
```

This shows the repo-scoped anchor, last successful sync time, and whether the
repo is the current default sync target.

### Step 3: Verify linked worktrees or scratch repos no longer poison the default repo

If you sync multiple repos/worktrees into the same brain DB, re-run sync on the
canonical repo and confirm it stays incremental instead of falling back to a
full reimport.

### Step 4: Done

```bash
mkdir -p ~/.gbrain/migrations
echo '{"version":"0.10.2","ts":"'$(date -u +%Y-%m-%dT%H:%M:%SZ)'","status":"complete"}' >> ~/.gbrain/migrations/completed.jsonl
```
